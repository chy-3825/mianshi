# CCS 独立使用与同一会话跨模型验收

本轮只验收 CC Switch（CCS）和 Codex，范围是 CCS 中已配置的所有非官方登录供应商卡片。当前本机卡片为 **kukuit、DeepSeek、卡扣AI**，三张卡片的 Codex 配置均使用 `model_provider = "custom"`。Clash 不作为启动、联网或历史记录的前提。各卡片使用自己的有效 API Key；具体模型 ID 以实际配置为准。

## 通过条件

1. **无 Clash 直连**：关闭 Clash，清空 CCS「设置 → 高级 → 全局代理」的地址，再启动 CCS 与 Codex。CCS 的出站请求应直连，不得受残留的 `HTTP_PROXY`、`HTTPS_PROXY` 或 `ALL_PROXY` 环境变量影响。逐张检查 kukuit、DeepSeek、卡扣AI：每张可用卡片均能完成真实问答和流式回复；失败时显示网络或上游错误，不得误报账号失效。
2. **同一对话跨模型**：在 Codex 中记录当前会话 ID 和历史标题，用卡片 A 的模型发送消息，在**同一个会话**切换到卡片 B 的模型并继续，再切回 A。对已有非官方卡片逐一往返。每次回复都能引用前文；历史列表始终只有该会话 ID 对应的一条记录。不能靠新建会话、复制记录或合并标题来满足此项。
3. **历史持久性**：切换供应商、重启 CCS 和 Codex、归档及恢复后，会话 ID、消息顺序、标题和归档状态保持正确。活动与归档目录短暂同时存在同一 ID 时，CCS 历史列表只显示一条，并选取最近活动的副本。失败请求不得覆盖原始 JSONL。
4. **数据一致性**：历史 JSONL 的 `session_meta.id` 不因切换模型而改变；Codex state DB 的同一逻辑线程不新增第二个 ID。CCS 的 `custom` 共享分组只改变会话归类，不改变会话 ID 或消息内容。

跨供应商的加密推理内容、工具调用和模型能力仍须用真实旧会话验证；仅编译成功或在列表中看到同一标题，不能算此项通过。验收时记录脱敏的会话 ID、请求结果和前后历史条数，不记录 API Key 或令牌。

## 本机更新

关闭 Codex 后运行桌面的 `更新CCS最新版.sh`。脚本从当前仓库源码构建前端与 Rust 程序，给现有 CCS 可执行文件、启动器及 SQLite 数据库做本地备份，然后替换 `~/.local/bin/cc-switch` 并启动新版。它不启动 Clash，也不把 Clash 代理变量带给 CCS。若检测到 Codex 正在运行，脚本会退出，现有 CCS 保持运行。备份位置会在脚本输出中显示。

旧 JSONL 会话记录在正常启动和设置保存时保持只读，不再自动迁移或还原。此前的离线迁移代码由显式维护开关保护，不属于本轮验收路径；本轮验收应在原会话 ID 上续聊并观察实际历史记录。
